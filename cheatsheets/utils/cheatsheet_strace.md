# strace — трассировка системных вызовов в Linux

`strace` показывает, какие **системные вызовы** совершает программа, с какими аргументами и чем они завершаются. Системный вызов — обращение программы к ядру Linux. Например, `openat()` открывает файл, `connect()` устанавливает сетевое соединение, а `execve()` запускает другую программу в текущем процессе. Трассировка помогает узнать, к какому пути обращается программа, где возникает ошибка и чего она ждёт.

## Установка

```bash
# Debian и Ubuntu
sudo apt install strace

# Fedora
sudo dnf install strace

strace -V
```

## Быстрый старт

```bash
strace -- ls .                   # запустить ls под трассировкой
strace -o trace.log -- ls .      # записать трассировку в файл
strace -p 12345                  # подключиться к существующему процессу
strace -f -p 12345               # также охватить потоки и новые дочерние процессы
```

После `--` указываются команда и её аргументы. В примерах с `-p` подставь свой PID — числовой идентификатор процесса. По умолчанию трассировка выводится в `stderr`, поток ошибок. Ключ `-o` пишет строки `strace` в файл отдельно от вывода самой программы. При подключении через `-p` команда `Ctrl+C` останавливает трассировку, а процесс продолжает работать. [Руководство strace(1)](https://man7.org/linux/man-pages/man1/strace.1.html)

| Ключ | Что делает |
|---|---|
| `-f` | Следит за новыми дочерними процессами и потоками. Вместе с `-p` подключается также ко всем существующим потокам указанного процесса |
| `-ff -o trace` | Пишет трассировку каждого процесса или потока в отдельный файл `trace.<ID>` |
| `-e trace=openat,close` | Оставляет только перечисленные системные вызовы |
| `-e status=failed` | Оставляет системные вызовы, вернувшие ошибку |
| `-tt` | Добавляет текущее время с микросекундами |
| `-T` | Добавляет длительность каждого системного вызова в секундах, например `<0.012345>` |
| `-y` / `-yy` | Дополняет номера файловых дескрипторов путями. `-yy` также показывает доступные сведения о сокетах |
| `-s 128` | Показывает до 128 байт содержимого строковых аргументов. Пути к файлам выводятся полностью |
| `-c` | Выводит сводку по числу вызовов, ошибкам и времени |
| `-C` | Выводит и обычную трассировку, и сводку |

## Как читать строку трассировки

Следующая команда покажет, какой путь пытается открыть `cat`. Для примера возьми имя файла, которого нет в текущем каталоге.

```bash
strace -e trace=openat -- cat ./missing.conf
```

Последняя попытка открытия может выглядеть так.

```text
openat(AT_FDCWD, "./missing.conf", O_RDONLY) = -1 ENOENT (No such file or directory)
```

- `openat` — имя системного вызова. В скобках идут его аргументы.
- `AT_FDCWD` означает, что относительный путь `./missing.conf` считается от текущего рабочего каталога процесса. `O_RDONLY` означает открытие для чтения.
- После `=` показан результат. При успешном `openat()` это число, например `3`. Такой **файловый дескриптор** — номер, по которому процесс дальше обращается к файлу или сокету.
- `-1 ENOENT` означает ошибку. `ENOENT` — имя кода ошибки, здесь оно указывает, что файла или одного из компонентов пути нет.

В многопоточной трассировке `<unfinished ...>` означает, что вызов ещё выполняется, а `<... resumed>` продолжает ту же запись. Сигналы идут отдельными строками, например `--- SIGCHLD ... ---` при изменении состояния дочернего процесса.

## Как выбрать нужные вызовы

В `-e trace=` можно передать имена через запятую или использовать группу.

| Выражение | Что попадёт в журнал |
|---|---|
| `-e trace=openat,read,close` | Только указанные вызовы |
| `-e trace=%file` | Вызовы, которым передают путь, например открытие файла и проверка его существования |
| `-e trace=%desc` | Операции с дескрипторами, например `read`, `write` и `close` |
| `-e trace=%network` | Сетевые вызовы, например `socket`, `connect` и `accept` |
| `-e trace=%process` | Создание процессов и потоков, `execve`, ожидание и завершение |
| `-e trace=%network,poll,ppoll,epoll_wait` | Сетевые вызовы вместе с указанными вызовами ожидания событий |

## Практические примеры

### Найти отсутствующий файл или отказ в доступе

```bash
strace -f -e trace=%file -e status=failed -o trace-files.log -- ./app
rg 'ENOENT|EACCES|EPERM' trace-files.log
```

Подставь команду своего приложения. `EACCES` означает отказ в доступе, а `EPERM` — отсутствие права на конкретную операцию. Смотри точный путь и процесс, которому вернулась ошибка. Например, обычный поиск библиотек может давать несколько `ENOENT`, прежде чем нужный файл найдётся по другому пути.

### Проверить подключение к локальному веб-сервису

```bash
strace -f -tt -T -yy -e trace=%network,poll,ppoll,epoll_wait \
  -o trace-net.log -- curl --noproxy '*' --connect-timeout 3 http://127.0.0.1:8080/
```

Подставь адрес и порт своего локального сервиса. Найди `connect()` с нужным адресом и проверь результат.

- `0` — вызов установил соединение.
- `EINPROGRESS` — соединение ещё устанавливается в неблокирующем режиме. В такой записи `poll()` может сообщить, что сокет готов, а `getsockopt(..., SO_ERROR, [0], ...)` подтверждает, что подключение завершилось успешно.
- `ECONNREFUSED` — подключение отклонено. Например, на порту может отсутствовать слушающий процесс.
- `ETIMEDOUT` — истёк срок ожидания подключения.

`SO_ERROR` — сохранённая ошибка сокета. Для проверки результата важен код внутри квадратных скобок в аргументах `getsockopt()`. Возврат `= 0` справа говорит лишь о том, что ядро успешно прочитало этот код. [Руководство connect(2)](https://man7.org/linux/man-pages/man2/connect.2.html)

### Понять, где процесс ждёт

```bash
strace -tt -T -e trace=clock_nanosleep,nanosleep -- sleep 1
```

У `sleep` вызов ожидания займёт примерно `<1.000000>` секунду. Для своего процесса можно сузить трассировку до вызовов ожидания.

```bash
trace_pid=12345  # PID проверяемого процесса
strace -f -tt -T -o trace-wait.log \
  -e trace=futex,poll,ppoll,epoll_wait,epoll_pwait,clock_nanosleep -p "$trace_pid"
```

`futex` используется для синхронизации потоков, например когда один поток ждёт освобождения блокировки. `poll` и `epoll_wait` ждут событий на дескрипторах, например готовности сокета к чтению. Долгое ожидание у сервиса без входящих запросов нормально. Если приложение в это время зависает, проверь, какой поток ждёт и повторяется ли это во время проблемы.

### Увидеть запуск дочерних процессов

```bash
strace -ff -o trace-process -e trace=%process -- sh -c 'ls > /dev/null; true'
rg 'execve\(' trace-process.*
```

Каждый файл относится к одному процессу или потоку. По строкам `execve` видно, какие исполняемые файлы запустила оболочка и какие аргументы передала им.

### Собрать сводку по вызовам

```bash
strace -c -- ls .
strace -c -w -- sleep 1
```

`calls` — число вызовов, `errors` — сколько вызовов вернули ошибку, `%time` — доля времени по строке в общей сводке. В `-c` по умолчанию учитывается процессорное время ядра. `-c -w` суммирует реальное прошедшее время внутри вызовов, включая ожидание. Поэтому во второй команде в сводке будет видна примерно секунда сна.

## Если подключение к PID отклонено

`strace` использует `ptrace` — интерфейс ядра для наблюдения за процессом. Если `-p` возвращает `Operation not permitted`, проверь владельца процесса и, если файл существует, настройку Yama в `/proc/sys/kernel/yama/ptrace_scope`.

```bash
ps -p 12345 -o pid,user,comm
if [ -r /proc/sys/kernel/yama/ptrace_scope ]; then
    cat /proc/sys/kernel/yama/ptrace_scope
fi
```

Yama — механизм безопасности ядра, который может ограничивать подключение даже к процессам того же пользователя. При `ptrace_scope=1` обычный разрешённый случай — трассировка потомка. Если можно повторить проблему в отдельном запуске, запусти новую копию приложения под `strace`. Трассировка приостанавливает процесс на системных вызовах и может влиять на измеряемые задержки. [Документация ядра Linux по Yama](https://docs.kernel.org/admin-guide/LSM/Yama.html)
