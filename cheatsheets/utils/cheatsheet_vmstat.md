## Базовый синтаксис

Примеры для `vmstat` из пакета системных утилит `procps-ng` в Linux. Утилита читает счётчики ядра из `/proc`. Это виртуальная файловая система, через которую ядро показывает состояние системы.

```
vmstat [опции] [задержка_сек] [количество_отчётов]
```

```bash
vmstat          # текущий снимок процессов и памяти, средние показатели с загрузки
vmstat 1        # отчёт каждую секунду, бесконечно (Ctrl+C для выхода)
vmstat 2 5      # первый отчёт сразу и ещё 4 замера с интервалом 2 секунды
```

В первом отчёте `procs` и `memory` уже показывают текущее состояние. Скорости и проценты в первом отчёте усреднены с момента загрузки. Для диагностики нагрузки за заданный интервал смотри со **второй строки данных** или используй `-y`, если опция есть в `vmstat --help`.

**cgroup** — группа процессов, для которой ядро учитывает использование ресурсов и может задать лимиты. Например, квота CPU ограничивает процессорное время, доступное группе за один период. В контейнере `vmstat` может показывать счётчики всего хоста, поэтому нагрузку конкретного контейнера сверяй с его метриками и лимитами cgroup.

## Поля вывода по умолчанию

```
procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----
 r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st
```

### procs — задачи

- `r` — задачи (процессы и потоки), которые выполняются на CPU или ждут процессорного времени. Логический CPU — единица, на которую планировщик может поставить поток. Одно физическое ядро может предоставлять несколько логических CPU.
- `b` — задачи, заблокированные в ожидании завершения I/O. Устойчивый рост стоит сопоставить с задержкой и очередью на блочных устройствах.

### memory — память (в КиБ по умолчанию)

- `swpd` — сколько места занято в swap, области подкачки.
- `free` — объём оперативной памяти (RAM), которая сейчас свободна.
- `buff` — память под буферы ядра для работы с блоками устройства. Буфер временно хранит данные, пока они передаются дальше.
- `cache` — память под кэш. Здесь `vmstat` учитывает страничный кэш и часть кэшей ядра, которую можно освободить (`SReclaimable`).

**Страница памяти** — единица, которой ядро управляет при работе с памятью. Размер обычной страницы на этой системе в байтах покажет `getconf PAGESIZE`. **Страничный кэш (page cache)** хранит данные файлов в RAM. Например, повторное чтение файла может обслужиться из памяти без обращения к SSD.

Опция `-a` выводит вместо `buff` и `cache` поля `active` и `inact` (`inactive`). К активным страницам обращались недавно. К неактивным обращались раньше, и ядро чаще рассматривает их как кандидатов на освобождение при нехватке RAM.

Для оценки запаса памяти смотри `available` в `free -h` (`MemAvailable` в `/proc/meminfo`). Это оценка памяти, доступной для новых задач без подкачки, с учётом того, какую часть кэша и других данных ядро может освободить. Низкое `free` само по себе часто объясняется кэшированием.

### swap — подкачка (КиБ/с по умолчанию)

**Swap** — область, куда ядро может временно выгружать страницы памяти, чтобы освободить RAM. Это может быть файл, раздел на диске или сжатое блочное устройство в памяти, например zram. Если приложению снова понадобятся выгруженные данные, ядро вернёт их в RAM.

- `si` — swap in, скорость возврата данных из swap в память.
- `so` — swap out, скорость выгрузки данных из памяти в swap.

Устойчивая подкачка вместе с низким `available` и ростом задержек указывает на давление на память. Разовый `si` может означать, что приложение снова обратилось к давно выгруженным страницам. `swpd` показывает объём уже занятого swap, а `si` и `so` — текущий обмен с ним.

### io — блочный ввод-вывод (КиБ/с)

**I/O (input/output)** — ввод-вывод. Поля `bi` и `bo` относятся к блочным устройствам, например SSD и жёстким дискам. Блочное устройство предоставляет данные порциями, которые можно читать и записывать по адресам.

- `bi` — скорость чтения данных с блочных устройств.
- `bo` — скорость записи данных на блочные устройства.

Это суммарный поток данных по системе. Старые версии `man vmstat` называют эти единицы блоками в секунду. В актуальном руководстве `procps-ng` они указаны как КиБ/с.

### system — система

- `in` — прерывания в секунду. Прерывание уведомляет CPU о событии, например о срабатывании таймера или завершении операции на устройстве.
- `cs` — переключения контекста в секунду. При переключении планировщик сохраняет состояние одного потока и передаёт CPU другому. Так бывает, например, когда поток ждёт чтения с диска. Для сравнения с обычной нагрузкой и поиска процессов с частыми переключениями используй `pidstat -w 1` из пакета `sysstat`.

### cpu — процессор (в %)

- `us` — время выполнения кода приложений, включая задачи с изменённым `nice`. `nice` влияет на то, как обычные задачи делят процессорное время при конкуренции.
- `sy` — время выполнения кода ядра, например при обработке системного вызова `read()`.
- `id` — время простоя CPU.
- `wa` — доля времени, которую ядро учло как простой при незавершённом I/O. На системах с несколькими CPU это приблизительная оценка.
- `st` — время, когда виртуальная машина ждала процессорного времени, пока физический CPU был выделен другой нагрузке. **Гипервизор** управляет виртуальными машинами и распределяет между ними ресурсы хоста.
- `gu` — время выполнения гостевых ВМ, если эта колонка есть в установленной версии.

## Полезные опции

```bash
vmstat -a          # active/inactive память вместо buff/cache
vmstat -s          # снимок памяти и накопленные счётчики событий
vmstat -m          # статистика кэшей объектов ядра (slab), нужен доступ к /proc/slabinfo
vmstat -d          # накопленные счётчики по дискам
vmstat -D          # общая сводка по дискам
vmstat -p sda1     # накопленные счётчики конкретного раздела
vmstat -f          # число созданных задач с загрузки, включая процессы и потоки
vmstat -n          # вывести шапку один раз
vmstat -t          # добавить метку времени к каждой строке
vmstat -w          # широкий вывод (удобнее читать)
vmstat -S M        # память в МиБ, si и so в МиБ/с
vmstat -y 1        # пропустить отчёт с загрузки, если версия поддерживает -y
```

`-S` принимает `k` (1000 байт), `K` (1024 байта, по умолчанию), `m` (1 000 000 байт) и `M` (1 048 576 байт). Единицы памяти и `si`/`so` меняются вместе, а `bi`/`bo` остаются в КиБ/с. Для наблюдения за небольшими объёмами подкачки оставляй КиБ/с, чтобы избежать округления до нуля.

## Slab — кэши объектов ядра

Ядро часто выделяет и освобождает небольшие структуры одинакового размера. Оно резервирует одну или несколько страниц памяти и делит их на слоты для таких объектов. Этот блок страниц называется **slab**. Один кэш может содержать много таких блоков. Например, `dentry` хранит связи между именами в каталогах и объектами файловой системы, а `inode` содержит метаданные файла, такие как права и размер.

Условная строка из `vmstat -m`.

```text
Cache                      Num    Total     Size    Pages
dentry                    8000    10080      192       42
```

- `Cache` — имя кэша.
- `Num` — сколько объектов сейчас используется. В примере 8000.
- `Total` — общее число выделенных слотов, включая свободные. В примере 10 080.
- `Size` — размер одного объекта в байтах. В примере 192 байта.
- `Pages` — в проверенных версиях procps-ng эта колонка выводит `objperslab`, то есть число слотов на один slab. В примере 42. Описание этой колонки в `man vmstat` расходится с кодом. [Исходник procps-ng 3.3.17](https://gitlab.com/procps-ng/procps/-/blob/v3.3.17/vmstat.c#L684) · [Исходник procps-ng](https://gitlab.com/procps-ng/procps/-/blob/master/src/vmstat.c#L729)

Для `vmstat -m` нужен доступ к `/proc/slabinfo`. Общий объём slab-памяти можно посмотреть через `/proc/meminfo`.

```bash
awk '/^(Slab|SReclaimable|SUnreclaim):/' /proc/meminfo
```

`Slab` — общий объём памяти под объекты ядра. `SReclaimable` — часть, которую ядро может попытаться освободить при нехватке RAM. `SUnreclaim` — часть, которую ядро не может освободить в ответ на нехватку RAM. Эту память освобождают подсистемы, которым принадлежат объекты. В `/proc/meminfo` эти значения указаны в КиБ, хотя суффикс в выводе — `kB`.

## Готовые рецепты

```bash
# мониторинг с метками времени и одной шапкой
vmstat -n -w -t 1

# десять секундных замеров для отчёта об инциденте
# из 11 строк данных удаляем первую, она идёт сразу после двух строк шапки
vmstat -n -w -t 1 11 | awk 'NR != 3'

# показывать только интервалы с активной подкачкой, сохраняя шапку
vmstat -n 1 | awk 'NR <= 2 || (NR > 3 && ($7 > 0 || $8 > 0))'

# активная/неактивная память и slab
vmstat -a 1 3
vmstat -m | head

# накопленные счётчики по дискам и выбранному разделу
vmstat -d
vmstat -p nvme0n1p2  # имя своего раздела можно узнать через lsblk

# активные устройства и их задержки за пять секундных интервалов (sysstat)
iostat -dxz -y 1 5
```

`iostat` из пакета `sysstat` показывает статистику отдельных устройств. `r_await` и `w_await` — среднее время завершения чтения и записи в миллисекундах, включая ожидание в очереди и обслуживание. `aqu-sz` — средняя длина очереди. Сравнивай с обычными значениями для того же устройства.

## Как читать: типовые сценарии

- **Высокий `us`** — нагрузка от приложений. Ищи процессы через `top`.
- **Высокий `sy`** — много работы ядра: системные вызовы, сеть, драйверы.
- **Высокий `wa` и растёт `b`** — проверь задержки и очередь устройств через `iostat -dxz -y 1 5`. Чтобы найти процессы с активным дисковым I/O, используй `pidstat -d 1`.
- **`r` устойчиво выше числа доступных CPU и `id` близок к нулю** — сверь число логических CPU через `nproc` и ищи потребителей через `pidstat -u 1`. В контейнере учитывай квоту CPU.
- **Устойчивая подкачка и низкий `available`** — проверь PSI памяти через `cat /proc/pressure/memory`. **PSI (Pressure Stall Information)** показывает, какую долю времени задачи задерживаются из-за ограничений ресурса. Например, `some avg10=12.50` означает, что за последние 10 секунд хотя бы одна задача задерживалась из-за давления на память примерно 12,5% времени. `full` учитывает интервалы, когда одновременно задерживались все задачи, у которых была работа.
- **Высокий `st` в VM** — часть процессорного времени гостю недоступна. Сопоставь с очередью `r` и проверь нагрузку и лимиты на стороне виртуализации.
