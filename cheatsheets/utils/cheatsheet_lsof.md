# lsof — открытые файлы и сокеты в Linux

`lsof` расшифровывается как *list open files*. Утилита показывает, какие файлы, каталоги, сетевые сокеты и другие ресурсы держат процессы. С её помощью можно найти владельца порта, понять, кто держит файл, или выяснить, почему после удаления большого лога место на диске не освободилось.

## Установка

```bash
# Debian и Ubuntu
sudo apt install lsof

# Fedora
sudo dnf install lsof

lsof -v
```

## Быстрый старт

```bash
lsof_pid=12345  # подставь PID процесса
lsof -p "$lsof_pid"                         # ресурсы процесса
lsof -- /var/log/myapp.log                  # процессы, открывшие этот файл
sudo lsof -nP -iTCP:8080 -sTCP:LISTEN       # процесс, слушающий TCP-порт 8080
```

В последней команде `-iTCP:8080` выбирает TCP-сокеты с портом `8080`. `-sTCP:LISTEN` оставляет сокеты, ожидающие входящих подключений. `-n` показывает адреса без поиска имён, а `-P` оставляет числовые порты. Это удобно, когда нужно увидеть `8080` прямо в выводе.

## Как читать вывод

Условный пример слушающего сокета.

```text
COMMAND   PID USER FD TYPE DEVICE SIZE/OFF NODE NAME
python3 12345 anna 3u IPv4 123456      0t0 TCP  127.0.0.1:8080 (LISTEN)
```

| Колонка | Что означает |
|---|---|
| `COMMAND`, `PID`, `USER` | Имя программы, идентификатор процесса и его пользователь |
| `FD` | Номер файлового дескриптора с режимом доступа или специальная метка ресурса |
| `TYPE` | Тип ресурса. Например, `REG` — обычный файл, `DIR` — каталог, `IPv4` и `IPv6` — сетевые сокеты |
| `DEVICE` | Идентификатор устройства или сведения о ресурсе, зависящие от его типа |
| `SIZE/OFF` | Размер файла в байтах или текущая позиция чтения и записи, если соответствующее значение доступно |
| `NODE` | Для обычного файла обычно номер inode, а для сетевого сокета может отображаться имя протокола |
| `NAME` | Путь к файлу или адрес сокета. Для TCP здесь также видно состояние соединения |

**Файловый дескриптор** — номер, которым процесс обозначает открытый ресурс. В примере `3u` означает дескриптор `3`, открытый на чтение и запись. Суффикс `r` означает чтение, `w` — запись. **Inode** — запись файловой системы с метаданными файла. Имя в каталоге указывает на эту запись.

В `FD` также встречаются метки `cwd` для рабочего каталога, `rtd` для корневого каталога процесса, `txt` для файла с кодом программы и `mem` для файлов, отображённых в память, например разделяемых библиотек.

## Как сочетать условия

При явном выборе разных групп обычные условия объединяются через **ИЛИ**. Например, `lsof -p 12345 -iTCP` может показать и файлы процесса `12345`, и TCP-сокеты других процессов. Ключ `-a` объединяет группы условий через **И**.

```bash
lsof -nP -a -p 12345 -iTCP    # только TCP-сокеты процесса 12345
lsof -a -p 12345 -d 0,1,2     # только его стандартные дескрипторы
```

Список `0,1,2` выбирает дескрипторы `0` (ввод), `1` (обычный вывод) или `2` (поток ошибок) внутри одной группы. `-a` связывает выбор дескрипторов с проверкой PID. [Руководство по ключам lsof](https://lsof.readthedocs.io/en/latest/options/)

## Практические примеры

### Найти владельца порта или посмотреть соединения

```bash
sudo lsof -nP -iTCP -sTCP:LISTEN               # все видимые слушающие TCP-сокеты
sudo lsof -nP -iTCP:8080 -sTCP:LISTEN          # кто ждёт подключений на 8080
sudo lsof -nP -iUDP:53                        # UDP-сокеты с портом 53
lsof -nP -a -p 12345 -iTCP -sTCP:ESTABLISHED  # установленные TCP-соединения процесса
lsof -a -p 12345 -U                           # локальные UNIX-сокеты процесса
```

`LISTEN` означает, что TCP-сокет ждёт входящих подключений. `ESTABLISHED` означает, что TCP-соединение установлено. В строке с `->` слева указан локальный адрес, справа — адрес второй стороны. У UDP нет состояния `LISTEN`. UNIX-сокет используется для связи процессов на одной машине и может быть представлен путём вроде `/run/myapp.sock`.

Например, строка `127.0.0.1:8080 (LISTEN)` показывает, что сервис привязан к локальному IPv4-адресу. Клиенты обращаются к нему через loopback, интерфейс связи с этой же машиной.

### Узнать, кто держит файл или каталог

```bash
lsof -- /var/log/myapp.log   # конкретный файл
lsof -t -- /var/log/myapp.log # только PID
lsof +d /var/log/myapp       # каталог и записи на первом уровне
lsof +D /var/log/myapp       # рекурсивно по дереву каталогов
```

`+D` обходит вложенные каталоги и на большом дереве может работать долго. При проблеме с размонтированием обрати внимание на строки `cwd`, `rtd` и открытые файлы. Например, `cwd` с путём внутри точки монтирования означает, что процесс использует этот каталог как рабочий.

### Найти удалённый файл, который занимает место

```bash
sudo lsof -nP +L1               # все видимые открытые файлы без имён в каталогах
lsof -nP -a -p 12345 +L1        # такие файлы у выбранного процесса
```

`+L1` выбирает открытые файлы, у которых осталось ноль жёстких ссылок. Жёсткая ссылка — имя в каталоге, указывающее на inode файла. В Linux в `NAME` может появиться `(deleted)`. Если процесс продолжает держать удалённый лог, `df` всё ещё учитывает его дисковые блоки, а `du` обходит доступные по именам файлы и может его пропустить. Сопоставь `PID`, `COMMAND` и `SIZE/OFF`, чтобы найти большой файл. Место освобождается, когда все процессы перестают использовать этот файл.

Этот пример в Bash создаёт временный файл, открывает его через дескриптор `3` и удаляет имя. До закрытия дескриптора `lsof` покажет файл с пометкой `(deleted)`.

```bash
(
    lsof_demo=$(mktemp) || exit 1
    printf 'test\n' > "$lsof_demo"
    exec 3<"$lsof_demo"
    rm -- "$lsof_demo"
    lsof -nP -a -p "$BASHPID" -d 3 +L1
    exec 3<&-
)
```

### Получить поля для скрипта

```bash
lsof -nP -a -p 12345 -iTCP -F pfn
```

Удобно читать вывод `-F` по первому символу строки. `p` задаёт PID, `f` — дескриптор, `n` — имя или сетевой адрес. Например, один процесс с открытым сокетом может выглядеть так.

```text
p12345
f3
n127.0.0.1:8080
```

## Если нужной строки нет

`lsof` показывает состояние в момент проверки. Для короткоживущего подключения повтори замер во время запроса или сравни с [захватом tcpdump](cheatsheet_tcpdump.md). Для чужих процессов и ресурсов контейнеров учитывай права доступа и контекст запуска. Предупреждение `Output information may be incomplete` означает, что часть ресурсов оказалась недоступна при проверке.
