# sar — статистика нагрузки Linux

`sar` входит в пакет `sysstat`. Он показывает нагрузку на CPU, память, диски и сеть в реальном времени и читает ранее собранные замеры. Например, после жалобы на медленную работу сервиса можно посмотреть, что происходило с сервером в нужные минуты.

## Установка

```bash
# Debian и Ubuntu
sudo apt install sysstat

# Fedora и RHEL
sudo dnf install sysstat

sar -V    # версия sysstat
```

## Живые замеры

```bash
sar -u 1 5         # пять замеров CPU с интервалом в одну секунду
sar -u -P ALL 1 5  # по каждому логическому CPU и по системе в целом
sar -u 1           # замеры каждую секунду до Ctrl+C
sar -u 0           # средняя загрузка CPU с момента запуска системы
```

При положительном интервале `sar` снимает начальные счётчики, ждёт один интервал и выводит первую строку замера. `sar -u 1 5` даёт пять секундных замеров. Строка `Average:` подводит итог по замерам этого запуска. Команда `sar` **без интервала** читает текущий дневной журнал.

### Что смотреть

| Команда | Что показывает |
|---|---|
| `sar -u 1 5` | Загрузку CPU и время ожидания ввода-вывода |
| `sar -u -P ALL 1 5` | Нагрузку по логическим CPU. Полезно, если один поток упирается в одно ядро |
| `sar -q 1 5` | Очередь на CPU, `load average` и задачи, ожидающие I/O |
| `sar -q PSI 1 5` | Сколько времени задачи задерживаются из-за конкуренции за CPU, память или I/O |
| `sar -r 1 5` | Свободную и доступную RAM, буферы и кэш |
| `sar -S 1 5` | Сколько места занято в swap |
| `sar -W 1 5` | Скорость обмена данными со swap |
| `sar -B 1 5` | Страничные ошибки и активность освобождения страниц памяти |
| `sar -b 1 5` | Общую интенсивность операций блочного I/O |
| `sar -d 1 5` | Скорость, очередь и задержки по отдельным блочным устройствам |
| `sar -F 1 5` | Свободное место и использование inode в файловых системах |
| `sar -n DEV,EDEV 1 5` | Трафик, ошибки и отброшенные пакеты по сетевым интерфейсам |
| `sar -n TCP,ETCP 1 5` | Активность TCP и повторные передачи по системе |
| `sar -w 1 5` | Число созданных задач и переключений контекста в секунду |

`-q PSI` требует поддержки и в ядре Linux, и в установленном `sysstat`. PSI расшифровывается как *Pressure Stall Information*. Например, `%smem-10` показывает долю времени за короткое окно в 10 секунд, когда хотя бы одна задача задерживалась из-за давления на память. Доступные отчёты можно проверить через `sar --help`.

## Как читать поля

### CPU и очередь

- `%user` и `%system` — время выполнения кода приложений и ядра соответственно. `%nice` учитывает пользовательские задачи с пониженным приоритетом.
- `%idle` — время простоя CPU без ожидающих операций дискового ввода-вывода. `%iowait` — время, которое ядро учло как простой при незавершённом I/O. Для поиска причины сопоставляй `%iowait` с `blocked` и задержками в `sar -d`.
- `%steal` — время, когда виртуальный CPU ждал, пока гипервизор выделял физический CPU другой нагрузке. Гипервизор распределяет ресурсы хоста между виртуальными машинами.
- `runq-sz` — сколько задач выполняется или готово выполняться на CPU в момент замера. `blocked` — сколько задач сейчас ждёт завершения I/O.
- `ldavg-1`, `ldavg-5`, `ldavg-15` — среднее число выполняющихся, готовых к выполнению и находящихся в непрерываемом сне задач за окна в 1, 5 и 15 минут. Непрерываемый сон — состояние ожидания внутри ядра, часто связанное с I/O. Например, `ldavg-1=12` на сервере с 8 логическими CPU стоит сопоставить с `runq-sz`, `blocked` и `%idle`, чтобы понять причину нагрузки.

`cswch/s` из `sar -w` показывает частоту переключений контекста. Это смена потока, который сейчас выполняется на CPU. Чтобы найти конкретные потоки и процессы, используй `pidstat -w 1`.

### Память и подкачка

- `kbmemfree` — RAM, которая сейчас свободна. `kbavail` — оценка памяти, доступной для новых приложений без подкачки, с учётом части кэша, которую ядро может освободить. Для оценки запаса RAM смотри `kbavail`.
- `kbcached` — память под кэш файловых данных. Кэш позволяет повторно читать данные из RAM. `kbbuffers` — память под буферы ядра для работы с блоками устройства.
- `kbswpused` из `sar -S` — занятый объём swap. Swap, или область подкачки, позволяет ядру временно выгрузить данные из RAM. `pswpin/s` и `pswpout/s` из `sar -W` показывают, сколько **страниц в секунду** возвращается в RAM и выгружается из неё. Страница — единица, которой ядро управляет при работе с памятью.
- `fault/s` из `sar -B` — число страничных ошибок, обработанных ядром за секунду. Ядро обрабатывает такую ошибку, когда программе нужно восстановить доступ к странице. `majflt/s` считает случаи, для которых понадобилось чтение данных через I/O, например чтение страницы файла или возврат страницы из подкачки.
- `pgscank/s` и `pgscand/s` из `sar -B` — сколько страниц в секунду ядро проверяет в поиске памяти, которую можно освободить. `pgscank/s` относится к фоновой работе, а `pgscand/s` — к работе в контексте задачи, запросившей память. `pgsteal/s` показывает, сколько страниц удалось освободить для повторного использования.

Размер обычной страницы в байтах можно узнать через `getconf PAGESIZE`. При странице 4096 байт `pswpout/s=200` соответствует примерно **800 КиБ/с**. Для сравнения `vmstat` по умолчанию уже выводит `si` и `so` в КиБ/с. [Шпаргалка по vmstat](cheatsheet_vmstat.md)

### Диск и файловая система

- `tps` — число запросов к устройству в секунду. `rkB/s` и `wkB/s` — скорости чтения и записи в КиБ/с.
- В сводном отчёте `sar -b` поля `bread/s` и `bwrtn/s` показывают чтение и запись в блоках по 512 байт в секунду. Например, `bread/s=200` соответствует 100 КиБ/с.
- `await` — среднее время выполнения запроса в миллисекундах. В него входят ожидание в очереди и само обслуживание. `aqu-sz` — среднее число запросов в очереди устройства.
- `%util` — доля времени, когда устройство обслуживало хотя бы один запрос. У NVMe и других устройств, способных обслуживать много запросов параллельно, этот показатель читай вместе с `await` и `aqu-sz`.
- В `sar -F` поля `%fsused` и `%Iused` показывают занятость места и inode. Inode хранит метаданные файла. При исчерпании inode новые файлы могут перестать создаваться, даже если на томе есть свободные байты.

### Сеть

- `rxkB/s` и `txkB/s` — скорости приёма и передачи в КиБ/с. `rxpck/s` и `txpck/s` — число пакетов в секунду.
- `rxerr/s` и `txerr/s` — ошибки приёма и отправки, `rxdrop/s` и `txdrop/s` — число пакетов, отброшенных в этих направлениях. Смотри строку нужного интерфейса в колонке `IFACE`.
- `retrans/s` в `sar -n ETCP` — повторно отправленные TCP-сегменты в секунду. TCP-сегмент — порция данных TCP с заголовком. Рост счётчика показывает, что пришлось передавать данные заново. Для проверки конкретного соединения нужны данные по этому соединению.

## История нагрузки

### Проверить сбор

История появляется, когда сборщик `sadc` записывает счётчики по расписанию. Обычно его вызывает `sa1` через таймер systemd или cron. Дневные файлы называются `saDD` или `saYYYYMMDD`. На Debian и Ubuntu их обычно ищут в `/var/log/sysstat/`, на системах семейства RHEL — в `/var/log/sa/`.

```bash
systemctl list-timers --all 'sysstat*'
systemctl cat sysstat-collect.timer   # расписание в OnCalendar
```

В системе с пакетным таймером systemd сбор можно включить командой `sudo systemctl enable --now sysstat.service sysstat-collect.timer`. Если пакет запускает сбор через cron и читает `/etc/default/sysstat`, проверь, что в этом файле установлено `ENABLED="true"`. Частоту и срок хранения проверяй в конфигурации своей системы. Например, `HISTORY` в `/etc/sysstat/sysstat` задаёт политику хранения дневных файлов.

### Прочитать интервал инцидента

```bash
sar -u                            # CPU за сегодня
sar -u -1                         # CPU за вчера
sar -q -r -W -1                   # вчерашние очередь, память и подкачка

sar_log=/var/log/sysstat/sa18     # подставь файл нужной даты
sar -u -q -r -W -d -f "$sar_log" -s 14:00:00 -e 14:20:00
sar -n DEV,EDEV -f "$sar_log" -s 14:00:00 -e 14:20:00
```

`-s` и `-e` задают границы окна по времени. Сверь дату в заголовке отчёта, особенно для коротких имён вроде `sa18`, где указан только день месяца. При интервале фонового сбора в 10 минут короткий всплеск может быть сглажен. Набор доступных исторических отчётов зависит от того, какие данные собирались. Например, сбор статистики отдельных дисков включается параметром `-S DISK` у `sadc`.

Пример разбора. В 14:10 вырос `ldavg-1`, но `runq-sz` остался низким, а `blocked` вырос. Если в те же минуты у одного устройства выросли `await` и `aqu-sz`, начни разбор с очереди I/O этого устройства. Если проблема ещё продолжается, `pidstat -d 1` поможет найти активные процессы.

## Записать замеры и выгрузить их

```bash
sar_capture_dir=$(mktemp -d)
sar_capture_file="$sar_capture_dir/sa-incident.bin"

sar -o "$sar_capture_file" 1 30     # записать 30 секундных замеров в бинарный файл
sar -u -r -d -f "$sar_capture_file" # перечитать нужные отчёты

sadf -d "$sar_capture_file" -- -u -r > "$sar_capture_dir/metrics.csv"
sadf -j "$sar_capture_file" -- -n DEV > "$sar_capture_dir/network.json"
```

В `sadf` после `--` идут параметры отчёта `sar`. `-d` выводит таблицу с разделителем `;`, `-j` — JSON. Бинарный файл удобно сохранить вместе с отчётом об инциденте, чтобы позже перечитать другие метрики из того же замера.
