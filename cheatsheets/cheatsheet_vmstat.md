## Базовый синтаксис

```
vmstat [опции] [задержка_сек] [количество_отчётов]
```

```bash
vmstat          # один отчёт со средними значениями с момента загрузки
vmstat 1        # отчёт каждую секунду, бесконечно (Ctrl+C для выхода)
vmstat 2 5      # 5 отчётов с интервалом 2 секунды
```

Первая строка при периодическом запуске — средние значения **с момента загрузки**, а не за интервал; на неё не ориентируйтесь, смотрите со второй строки.

## Поля вывода по умолчанию

```
procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----
 r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st
```

### procs — процессы

- `r` — процессы в очереди на выполнение (running/runnable). Если стабильно больше числа ядер — CPU перегружен.
- `b` — процессы в непрерываемом сне (обычно ждут I/O). Рост указывает на проблемы с диском/блокировками.

### memory — память (в КиБ по умолчанию)

- `swpd` — использовано swap.
- `free` — свободная память.
- `buff` — память под буферы.
- `cache` — память под страничный кэш.

Важно: `free` маленькое — это нормально, Linux использует память под кэш. Реально доступная память ≈ `free + buff + cache` (точнее — смотрите `free -h`, поле `available`).

### swap — подкачка (КиБ/с)

- `si` — swap in, чтение из swap в память.
- `so` — swap out, выгрузка в swap.

Ненулевые `si`/`so` **постоянно** — признак нехватки памяти (thrashing). Разовые всплески допустимы.

### io — ввод/вывод (блоки/с)

- `bi` — блоки, прочитанные с блочного устройства.
- `bo` — блоки, записанные на блочное устройство.

### system — система

- `in` — прерывания в секунду (включая часы).
- `cs` — переключения контекста в секунду. Очень высокие `cs` при низком `us` — много переключений без полезной работы.

### cpu — процессор (в %)

- `us` — пользовательский код.
- `sy` — код ядра.
- `id` — простой.
- `wa` — ожидание I/O. Высокий `wa` — узкое место диск/сеть, а не CPU.
- `st` — время, «украденное» гипервизором (актуально в VM).

## Полезные опции

```bash
vmstat -a          # active/inactive память вместо buff/cache
vmstat -s          # сводка счётчиков памяти и событий с загрузки (одним списком)
vmstat -m          # статистика slab (кэши ядра)
vmstat -d          # статистика по дискам
vmstat -p sda1     # статистика по конкретному разделу
vmstat -f          # число fork() с момента загрузки
vmstat -t          # добавить метку времени к каждой строке
vmstat -w          # широкий вывод (удобнее читать)
vmstat -S M        # единицы памяти: k/K, m/M, g/G (K=1000, k=1024)
```

## Готовые рецепты

```bash
# мониторинг с метками времени и человекочитаемыми единицами
vmstat -w -t -S M 1

# снимок нагрузки за 10 секунд для отчёта об инциденте
vmstat -w -t 1 10

# только память: следим за swap in/out
vmstat 1 | awk 'NR<=2 || $7>0 || $8>0'

# активная/неактивная память и slab
vmstat -a 1 3
vmstat -m | head

# диски: какой раздел генерирует нагрузку
vmstat -d
vmstat -p nvme0n1p2
```

## Как читать: типовые сценарии

- **Высокий `us`** — нагрузка от приложений; ищите процесс через `top`/`ps`.
- **Высокий `sy`** — много работы ядра: системные вызовы, сеть, драйверы.
- **Высокий `wa` + растёт `b`** — процессы ждут I/O; проверяйте диски (`iostat`, `iotop`).
- **`r` > числа ядер** — очередь на CPU, нехватка процессорного времени.
- **Постоянные `si`/`so`** — нехватка RAM, система свопится; добавить память или уменьшить потребление.
- **Высокий `st` в VM** — гипервизор не даёт процессорного времени; проблема на стороне хоста.
- **Очень высокий `cs`** — чрезмерные переключения контекста (много потоков/процессов).

## Частые ошибки

- Судить о памяти по `free`: маленькое `free` при большом `cache` — норма, а не утечка.
- Смотреть на первую строку при периодическом запуске: это средние с загрузки, а не текущие значения.
- Путать `wa` с загрузкой CPU: это ожидание I/O, а не вычисления.
- Считать любой swap плохим: опасен именно постоянный `si`/`so`, а не сам факт `swpd > 0`.
