# Что нового в PHP 8.2: readonly-классы, новые типы и Randomizer

PHP 8.2 вышел 8 декабря 2022 года. Главные изменения расширяют систему типов и объектную модель: появились readonly-классы, отдельные типы `null`, `true` и `false`, а также возможность описать сложные сочетания типов. В стандартной библиотеке появился объектный API генерации случайных чисел. [Официальный анонс PHP 8.2](https://www.php.net/releases/8.2/ru.php)

## Readonly-классы

Если каждый экземпляр класса представляет неизменяемые данные, раньше приходилось объявлять каждое свойство отдельно как `readonly`. В PHP 8.2 этот режим можно задать всему классу:

    final readonly class UserCard
    {
        public function __construct(
            public string $name,
            public string $email,
        ) {}
    }

    $card = new UserCard('Ada', 'ada@example.com');

    echo $card->name; // Ada
    // $card->name = 'Grace'; // Ошибка: свойство только для чтения

Readonly-класс может содержать только типизированные свойства; их нельзя переназначать после инициализации. Но это не глубокая неизменяемость: если свойство ссылается на изменяемый объект, его собственное состояние всё ещё может измениться.

    readonly class Report
    {
        public function __construct(
            public DateTime $createdAt,
        ) {}
    }

    $report = new Report(new DateTime());
    $report->createdAt->modify('+1 day'); // объект DateTime меняется

Если объект должен быть неизменяемым и внутри, используйте неизменяемые типы, например `DateTimeImmutable`, или копируйте вложенное состояние.

## Отдельные типы `null`, `true` и `false`

В PHP 8.2 `null`, `true` и `false` можно указывать как самостоятельные типы. Это помогает точнее описывать результат функции, которая возвращает ровно одно из этих значений:

    function lookupUser(int $id): User|false
    {
        // Вернёт объект пользователя или false, если запись не найдена.
    }

    function resetCache(): null
    {
        // Функция всегда возвращает null.
        return null;
    }

    function isAvailable(): true
    {
        return true;
    }

До PHP 8.2 `false` и `null` нельзя было использовать как самостоятельные типы: их можно было включить в объединение, но нельзя было описать функцию, которая возвращает только `false` или только `null`. Тип `bool` по-прежнему подходит, если функция может вернуть оба логических значения.

## DNF-типы: объединение пересечений

Пересечение типов означает, что значение должно соответствовать сразу нескольким типам, например интерфейсам `Stringable` и `JsonSerializable`. Объединение типов означает `один тип или другой`. PHP 8.2 разрешил сочетать эти конструкции, если пересечение заключено в скобки:

    function encodeForLog(
        (Stringable&JsonSerializable)|null $value,
    ): string {
        if ($value === null) {
            return 'null';
        }

        return json_encode($value, JSON_THROW_ON_ERROR);
    }

Теперь тип может прямо описать `объект, который реализует оба интерфейса, либо null`. Раньше такое условие приходилось проверять в теле функции с несколькими `instanceof`.

## Новый модуль Random

В PHP 8.2 появился объектный API генерации случайных чисел. Класс `Random\Randomizer` предоставляет операции вроде получения случайного числа, перемешивания массива и выбора случайного ключа:

    $randomizer = new \Random\Randomizer();

    $dice = $randomizer->getInt(1, 6);
    $shuffled = $randomizer->shuffleArray(['red', 'green', 'blue']);

Без аргументов `Randomizer` использует криптографически стойкий источник, поэтому это подходит для случайных значений в рабочих приложениях. При необходимости можно передать собственный движок. Это позволяет разделить независимые последовательности, а в тестах — выбрать движок, состояние которого можно задать и воспроизвести.

Старые функции `rand()` и `mt_rand()` остаются в языке. Новый API удобнее, когда важно явно контролировать источник случайности и состояние генератора. Для секретов, токенов и случайных паролей используйте криптографически стойкий движок, а не предсказуемый генератор с фиксированным seed.

## Константы в трейтах

Трейт может объявлять собственные константы. Они доступны через класс, который использует трейт:

    trait HasStatus
    {
        public const READY = 'ready';
    }

    final class Job
    {
        use HasStatus;
    }

    echo Job::READY; // ready

Константа является частью класса-потребителя; обращаться к ней через имя трейта нельзя.

## Защита секретов в трассировках

Атрибут `#[\SensitiveParameter]` помечает параметр, значение которого не следует показывать в трассировке стека:

    function connectToDatabase(
        string $host,
        #[\SensitiveParameter] string $password,
    ): void {
        // Открыть соединение.
    }

Если во время вызова возникнет исключение, PHP скроет пароль в диагностических данных backtrace. Атрибут защищает именно трассировку; он не шифрует значение и не скрывает его из других логов, дампов или кода приложения.

## Небольшие, но полезные функции

- **SQL-запрос с параметрами.** `mysqli_execute_query()` за один вызов подготавливает SQL, связывает значения с маркерами и выполняет запрос. Например, пользователь может прислать строку `' OR '1'='1`:

      $email = "' OR '1'='1";
      $result = $mysqli->execute_query(
          'SELECT id FROM users WHERE email = ?',
          [$email],
      );

  Здесь `?` — место для одного значения, а второй аргумент — массив значений в том же порядке, в котором стоят маркеры. PHP не вставляет строку пользователя в текст SQL: запрос подготавливается отдельно, а значение передаётся как параметр. Поэтому кавычка и текст `OR 1=1` останутся частью искомого email, а не превратятся в оператор SQL.

  В небезопасном варианте склейки та же строка могла бы изменить условие `WHERE`:

      // Не делайте так: ввод становится частью SQL-кода.
      $sql = "SELECT id FROM users WHERE email = '$email'";

  При строке из примера итоговое условие будет `email = '' OR '1'='1'`. Вторая часть всегда истинна, поэтому запрос может вернуть чужие записи. С параметром `?` та же строка сравнивается с email как одно значение и условие `WHERE` не меняется.

  Количество значений в массиве должно совпадать с количеством `?`. Маркеры подходят для значений, например в `WHERE` или `VALUES`, но не для имён таблиц и столбцов. Если имя столбца выбирает пользователь, выбирайте его из заранее заданного списка. [Руководство mysqli_execute_query()](https://www.php.net/manual/ru/mysqli.execute-query.php)

- **Конфигурация и память.** `ini_parse_quantity()` разбирает значения размеров вроде `1G`, а `memory_reset_peak_usage()` сбрасывает зарегистрированный пиковый расход памяти. Последняя функция полезна для измерений в долгоживущих процессах.
- **Расширения.** Добавлены `curl_upkeep()` для обслуживания соединения cURL, новые функции ODBC, поддержка XChaCha20 в Sodium и получение длины ключа шифра в OpenSSL. В PCRE появилась опция `n`, которая отключает автоматический захват простых групп в регулярном выражении.

## Динамические свойства теперь устаревают

Если присвоить объекту свойство, которое не объявлено в классе, PHP 8.2 выдаёт `E_DEPRECATED`:

    final class User
    {
        public string $name;
    }

    $user = new User();
    $user->name = 'Ada';        // Объявленное свойство — нормально
    $user->lastName = 'Byron';  // E_DEPRECATED

Обычно правильное исправление — объявить свойство в классе. Если класс намеренно служит контейнером произвольных значений, можно временно разрешить это атрибутом `#[\AllowDynamicProperties]`. Для классов, которыми вы не владеете, но к которым нужно привязать дополнительные данные, удобен `WeakMap`. Экземпляры `stdClass` и классы, которые реализуют `__get()`/`__set()`, этой депрекации не затронуты.

## Другие изменения при переходе

- Интерполяция строк с долларом и фигурными скобками объявлена устаревшей. Используйте `$name` или `{$name}`.
- Функции `utf8_encode()` и `utf8_decode()` объявлены устаревшими: они всегда предполагали конкретное соответствие между Latin-1 и UTF-8, которое часто не совпадает с реальной кодировкой входных данных. Для преобразования указывайте исходную кодировку явно в `mb_convert_encoding()` или `iconv()`.
- Функции `strtolower()` и `strtoupper()` больше не зависят от локали и преобразуют только ASCII. Для букв других алфавитов используйте функции `mbstring`, например `mb_strtolower()`.
- Создание динамических свойств — депрекация, а не немедленная ошибка. `stdClass` по-прежнему разрешает такие свойства.

Полный список новых API, несовместимостей и устареваний см. в [официальном руководстве по миграции с PHP 8.1 на PHP 8.2](https://www.php.net/manual/ru/migration82.php).
