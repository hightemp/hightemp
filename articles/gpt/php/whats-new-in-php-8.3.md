# Что нового в PHP 8.3: типизированные константы, Override и Randomizer

PHP 8.3 вышел 23 ноября 2023 года. В этой версии константам добавили типы, появился атрибут `#[\Override]`, а readonly-объекты стало можно глубоко клонировать. Ещё одно крупное изменение — развитие объектного API генерации случайных чисел, появившегося в PHP 8.2. [Официальный анонс PHP 8.3](https://www.php.net/releases/8.3/ru.php)

Примеры ниже требуют PHP 8.3 или новее. Полный список новых функций и изменений совместимости доступен в [официальном руководстве по миграции с PHP 8.2 на PHP 8.3](https://www.php.net/manual/ru/migration83.php).

## Типизированные константы классов

До PHP 8.3 тип константы никак не фиксировался. Интерфейс мог ожидать строку, а реализующий его класс случайно объявить массив. Теперь тип можно указать прямо в объявлении:

    interface HasVersion
    {
        public const string VERSION = '1.0';
    }

    final class Application implements HasVersion
    {
        public const string VERSION = '1.1';
    }

Если вместо строки объявить массив, PHP остановит выполнение с ошибкой типа. Типизированные константы работают в классах, интерфейсах, трейтах и перечислениях. Это помогает фиксировать контракт конфигурационных значений и ловить несоответствие там, где оно объявлено, а не в более позднем месте использования.

## Динамическое имя константы

Если имя константы хранится в переменной, в PHP 8.3 её можно прочитать напрямую:

    final class Release
    {
        public const string VERSION = '8.3';
    }

    $name = 'VERSION';
    echo Release::{$name}; // 8.3

До этого приходилось собирать строку вроде `Release::VERSION` и передавать её в `constant()`. Новый синтаксис удобнее читать и анализировать инструментами разработки.

## `#[Override]` защищает от опечаток при переопределении

Атрибут `#[\Override]` указывает, что метод должен переопределять метод родителя или реализуемого интерфейса:

    class TestCase
    {
        protected function tearDown(): void {}
    }

    final class UserTest extends TestCase
    {
        #[\Override]
        protected function tearDown(): void
        {
            // Освобождение ресурсов теста.
        }
    }

Если ошибиться в имени, например написать `tearDwon`, PHP выдаст ошибку вместо того, чтобы молча создать новый метод и пропустить ожидаемую очистку. Атрибут особенно полезен при переименовании методов в базовом классе или при реализации интерфейсов.

## Глубокое клонирование readonly-объектов

Readonly-свойство запрещает заменить значение после его инициализации. До PHP 8.3 это мешало методу `__clone()` заменить вложенный объект его отдельной копией. В PHP 8.3 readonly-свойство разрешено один раз переинициализировать внутри `__clone()`:

    final class Metadata
    {
        public int $revision = 1;
    }

    readonly class Snapshot
    {
        public function __construct(
            public Metadata $metadata,
        ) {}

        public function __clone(): void
        {
            $this->metadata = clone $this->metadata;
        }
    }

    $original = new Snapshot(new Metadata());
    $copy = clone $original;

    $copy->metadata->revision = 2;

    echo $original->metadata->revision; // 1
    echo $copy->metadata->revision;     // 2

Без повторного клонирования оба объекта ссылались бы на один и тот же изменяемый `Metadata`. Это глубокое клонирование: копируется не только внешний объект, но и указанное вложенное состояние. PHP клонирует только то, что код явно копирует в `__clone()`.

## `json_validate()`: проверить JSON, не создавая дерево данных

Если приложению нужно лишь понять, корректен ли JSON, раньше часто вызывали `json_decode()` и затем проверяли `json_last_error()`. Функция `json_validate()` выполняет именно проверку:

    $payload = '{"user":{"id":42}}';

    if (!json_validate($payload)) {
        throw new InvalidArgumentException('Некорректный JSON');
    }

Это полезно, когда нужно проверить или пропустить JSON дальше без построения массива или объекта в памяти. Если приложению нужны сами данные, вызывайте `json_decode()` сразу: сначала валидировать, а затем декодировать означает разобрать одну строку дважды.

## Улучшения генератора случайных чисел

В PHP 8.2 появился модуль `Random` с объектами-движками и классом `Randomizer`. PHP 8.3 добавил генерацию случайных строк из выбранного набора байтов и чисел с плавающей точкой:

    $randomizer = new \Random\Randomizer();

    $code = $randomizer->getBytesFromString(
        'ABCDEFGHJKLMNPQRSTUVWXYZ23456789',
        10,
    );

    $temperature = $randomizer->getFloat(-10.0, 40.0);

`getBytesFromString()` удобно использовать для кодов, где нужно исключить похожие символы, например `0` и `O`. `getFloat()` и `nextFloat()` правильно обрабатывают границы диапазона и не требуют писать собственный алгоритм на основе `random_int()`.

По умолчанию `Randomizer` использует криптографически стойкий источник случайных чисел. Для тестов можно передать ему движок с заданным состоянием, чтобы воспроизводить последовательность. Для секретов, токенов и случайных паролей используйте безопасный движок по умолчанию.

## Строковые и DOM-функции

- `str_increment()` и `str_decrement()` выполняют последовательное увеличение и уменьшение буквенно-цифровых строк. Например, `str_increment('Z')` даёт `AA`, а `str_increment('99')` — `100`. Это отдельная операция над строкой, а не замена арифметики над числами.
- `mb_str_pad()` дополняет строку до нужной ширины с учётом многобайтной кодировки.
- В DOM добавили `DOMElement::getAttributeNames()`, `toggleAttribute()`, `insertAdjacentElement()` и `insertAdjacentText()`, а также методы проверки и замены узлов.
- Для `DatePeriod` появился `createFromISO8601String()`, а для ошибок даты — отдельные классы исключений. Вместо одного общего исключения приложение может обработать ошибку формата даты, интервала или часового пояса отдельно.

## Типы, конфигурация и командная строка

PHP 8.3 расширил систему типов ещё одним способом: теперь объединение может содержать пересечение типов. Например, `(Logger&Formatter)|null` означает `объект одновременно Logger и Formatter либо null`. Это позволяет выразить контракт в типе, который раньше приходилось проверять несколькими условиями `instanceof`.

Кроме того:

- Константы теперь можно объявлять в трейтах и получать через класс, который использует трейт.
- В константных выражениях можно обращаться к свойствам перечислений, например к значению backed enum.
- Статические локальные переменные могут инициализироваться выражениями и вызовами функций.
- CLI-команда `php -l` принимает несколько имён файлов за один запуск.
- Конфигурация `php.ini` понимает резервные значения для переменных окружения.
- Появилась INI-директива `zend.max_allowed_stack_size` для ограничения стека вызовов.

## Что проверить при переходе

В PHP 8.3 устарели неявные операции над нечисловыми строками:

    $name = 'Z';
    $name++; // Устаревающее поведение

    $name = str_increment($name); // Явная операция со строкой

Также объявлены устаревшими вызовы `get_class()` и `get_parent_class()` без аргументов. Вместо них можно использовать `$object::class` или передавать объект явно. Настройки `assert.*` и функция `assert_options()` тоже объявлены устаревшими.

Поведение некоторых функций стало строже: `range()` теперь выдаёт ошибки для недопустимых границ и шага, а при передаче строковых границ может построить диапазон символов. Функции `strtolower()` и `strtoupper()` больше не учитывают системную локаль и преобразуют только ASCII. Для многобайтного текста используйте функции расширения `mbstring`, например `mb_strtolower()`.

Перед обновлением проверьте [полный список несовместимых изменений и устареваний](https://www.php.net/manual/ru/migration83.php). Особенно полезно прогнать тесты, если код использует `range()`, динамические callbacks или нестандартное поведение строк.
