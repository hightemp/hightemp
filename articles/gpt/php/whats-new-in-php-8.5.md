# Что нового в PHP 8.5: pipe-оператор, URI API и обновлённый clone

PHP 8.5 вышел 20 ноября 2025 года. Это уже стабильная версия языка. Среди главных новшеств — оператор конвейера `|>`, встроенный API для URI и URL, клонирование объекта с изменением свойств и атрибут `#[\NoDiscard]`. Версия также добавляет новые функции массивов и улучшает диагностику ошибок. [Официальный анонс PHP 8.5](https://www.php.net/releases/8.5/ru.php)

Примеры в статье рассчитаны на PHP 8.5 и новее. Некоторые небольшие дополнения к расширениям перечислены отдельно: полный перечень API и несовместимых изменений есть в [официальном руководстве по переходу с PHP 8.4 на PHP 8.5](https://www.php.net/manual/ru/migration85.php).

## Pipe-оператор: читать преобразования по порядку

Оператор `|>` передаёт значение слева в callable справа как единственный аргумент. Тип значения не ограничен: слева могут быть строки, массивы, объекты и другие значения. Поэтому последовательность преобразований можно читать слева направо, не вкладывая вызовы друг в друга:

    $name = '  ADA LOVELACE  '
        |> trim(...)
        |> mb_strtolower(...)
        |> (fn (string $value): string =>
            mb_convert_case($value, MB_CASE_TITLE, 'UTF-8'));

    echo $name; // Ada Lovelace

Три точки после имени функции создают first-class callable — вызываемое значение, которое можно передать оператору. Для преобразования с несколькими аргументами подойдёт замыкание:

    $text = 'PHP 8.5'
        |> (fn (string $value): string =>
            str_replace(' ', '-', $value))
        |> strtolower(...);

### Пример с массивом

Функция `array_filter()` принимает и массив, и callback, поэтому её оборачивают в замыкание, которому pipe передаст массив. Следующая функция получает отфильтрованный список:

    $users = [
        ['name' => 'Ada', 'active' => true],
        ['name' => 'Grace', 'active' => false],
    ];

    $activeNames = $users
        |> (fn (array $items): array => array_filter(
            $items,
            static fn (array $user): bool => $user['active'],
        ))
        |> (fn (array $items): array => array_column($items, 'name'))
        |> array_values(...);

    // ['Ada']

### Пример с объектом

Объект также передаётся в первый callable цепочки. Здесь сначала из объекта собирается подпись, затем строка экранируется для HTML:

    final class UserProfile
    {
        public function __construct(
            public string $name,
            public string $email,
        ) {}
    }

    $profile = new UserProfile(' Ada ', ' ada@example.com ');

    $label = $profile
        |> (fn (UserProfile $user): string =>
            trim($user->name) . ' <' . trim($user->email) . '>')
        |> htmlspecialchars(...);

Оператор не передаёт данные как поток и не меняет функции. Каждый шаг получает одно предыдущее значение. Если используемая функция требует несколько обязательных аргументов, оберните её вызов в замыкание, которое примет значение из pipe и добавит остальные аргументы. Если для цепочки нужны длинные или сильно разные операции, обычные промежуточные переменные могут оставаться понятнее.

## Новый URI API

В стандартной библиотеке появился модуль `Uri` для разбора, проверки, нормализации и изменения адресов. Он поддерживает два разных набора правил:

- `Uri\Rfc3986\Uri` обрабатывает URI по RFC 3986;
- `Uri\WhatWg\Url` следует [WHATWG URL Standard](https://url.spec.whatwg.org/), на который ориентируются браузеры.

[RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) задаёт общую грамматику URI-ссылок и правила разбора их частей и разрешения относительных ссылок. Например, в `https://example.com:8443/docs?q=php#api` схема — `https`, authority — `example.com:8443`, путь — `/docs`, query — `q=php`, fragment — `api`. Стандарт определяет общую структуру, но не то, как каждая схема получает ресурс: это задаёт сама схема. URI служит идентификатором ресурса; URL — подмножество URI, которое также указывает способ или место доступа к ресурсу.

Это разделение важно: адрес, принимаемый браузером, и URI, разбираемый по RFC 3986, не всегда имеют одинаковую интерпретацию. Выбирайте класс по ожидаемым правилам разбора.

    $uri = new \Uri\Rfc3986\Uri(
        'https://example.com:8443/docs?q=php'
    );

    echo $uri->getHost(); // example.com

URI-объекты неизменяемые: методы вида `withHost()` или `withPath()` возвращают обновлённый объект, а исходный остаётся прежним. Это удобно для последовательной нормализации адреса и уменьшает число ручных операций со строкой. Существующий `parse_url()` не исчез; новый модуль предоставляет более явные типы и поведение по стандартам.

## Клонирование с заменой свойств

В PHP 8.5 выражение `clone` можно вызвать с массивом новых значений для копии объекта. Это упрощает неизменяемые value objects: метод `withX()` создаёт новый объект и меняет только выбранное свойство.

    final readonly class Point
    {
        public function __construct(
            public int $x,
            public int $y,
        ) {}

        public function withX(int $x): self
        {
            return clone($this, ['x' => $x]);
        }
    }

    $point = new Point(3, 5);
    $moved = $point->withX(10);

    echo $point->x; // 3
    echo $moved->x; // 10

Исходный объект не меняется. Для клона PHP сначала выполняет существующий метод `__clone()`, затем применяет переданные значения. Проверки доступа и хуки свойств продолжают действовать, поэтому менять можно только свойства, доступные в текущей области видимости. Это особенно важно для readonly-свойств: когда инвариант должен сохраняться, проверку значения полезно задавать в хуке `set`, а не только в конструкторе.

## `#[NoDiscard]`: заметить проигнорированный результат

Атрибут `#[\NoDiscard]` помечает результат функции или метода как важный. Если вызывающий код никак не использует это значение, PHP выдаёт предупреждение:

    #[\NoDiscard]
    function normalizeEmail(string $email): string
    {
        return strtolower(trim($email));
    }

    normalizeEmail('User@example.com'); // Предупреждение: результат потерян

    $email = normalizeEmail('User@example.com'); // Результат сохранён

Если результат действительно нужно отбросить, это можно обозначить явно с помощью приведения `(void)`:

    (void) normalizeEmail('User@example.com');

Атрибут полезен для функций, где игнорирование результата почти наверняка означает ошибку: например, для нормализации, преобразования или вычисления значения. Он не делает результат обязательным на уровне типов и не заменяет анализатор кода, но помогает заметить распространённую ошибку во время выполнения.

## Замыкания в константных выражениях

Статические замыкания и first-class callables теперь разрешены в местах, где PHP требует константное выражение: например, в значениях параметров по умолчанию и аргументах атрибутов.

    function normalize(
        string $value,
        \Closure $normalizer = static function (string $value): string {
            return trim($value);
        },
    ): string {
        return $normalizer($value);
    }

Замыкание должно быть `static`: оно не захватывает переменные из окружающего кода через `use` и не обращается к `$this`. Это сохраняет свойство константного выражения — его можно определить заранее, не опираясь на изменяющееся состояние.

## Массивы и локализованное форматирование

Функции `array_first()` и `array_last()` возвращают первый и последний элемент массива, не двигая его внутренний указатель:

    $first = array_first($items);
    $last = array_last($items);

Для пустого массива обе функции возвращают `null`. Они возвращают именно значение; чтобы получить ключ, по-прежнему нужны `array_key_first()` и `array_key_last()`.

### `IntlListFormatter`: список как фраза на нужном языке

Обычный `implode(', ', $items)` просто вставляет запятые. `IntlListFormatter` превращает массив текстовых элементов в естественно оформленный список с союзами и пунктуацией, принятыми в выбранной локали. Это удобно для подписей вроде `чай, кофе и молоко` или `чай, кофе или молоко` в интерфейсе.

Конструктор принимает локаль, тип связи и ширину оформления:

    $items = ['чай', 'кофе', 'молоко'];

    $and = new IntlListFormatter(
        'ru_RU',
        IntlListFormatter::TYPE_AND,
        IntlListFormatter::WIDTH_WIDE,
    );
    echo $and->format($items); // чай, кофе и молоко

    $or = new IntlListFormatter(
        'ru_RU',
        IntlListFormatter::TYPE_OR,
        IntlListFormatter::WIDTH_WIDE,
    );
    echo $or->format($items); // чай, кофе или молоко

`TYPE_AND` оформляет список с союзом `и`, `TYPE_OR` — с `или`. `TYPE_UNITS` предназначен для составных единиц измерения, например списка величин `3 ft, 7 in`. Ширина `WIDTH_WIDE`, `WIDTH_SHORT` или `WIDTH_NARROW` выбирает полный, краткий или компактный вариант пунктуации и словоформ. Метод `format()` принимает массив и возвращает готовую строку либо `false` при ошибке. Требуется расширение `intl` и ICU 67 или новее. [Документация IntlListFormatter](https://www.php.net/manual/ru/class.intllistformatter.php)

## Другие заметные изменения

- **Ограничение памяти на уровне сервера.** Директива `max_memory_limit` задаёт верхнюю границу для `memory_limit`. Например, администратор может установить потолок 512 МБ, чтобы код приложения не мог повысить лимит отдельного запроса выше этого значения. Значение `-1` означает, что дополнительного потолка нет.
- **Диагностика фатальных ошибок.** Для некоторых фатальных ошибок PHP теперь может вывести стек вызовов, помогая найти цепочку функций, которая привела к проблеме.
- **Получение текущих обработчиков.** Функции `get_error_handler()` и `get_exception_handler()` возвращают установленные обработчики ошибок и исключений. Раньше для этого приходилось временно подменять обработчик, а затем восстанавливать его.
- **Фильтрация с исключением.** Флаг `FILTER_THROW_ON_FAILURE` позволяет запросить исключение при провале фильтра вместо результата `false` или `null`.
- **Изменения свойств и атрибутов.** Асимметричная видимость теперь работает и со статическими свойствами. Атрибут `#[\Override]` можно ставить на свойства; PHP проверяет, что такое свойство есть у родителя. Также разрешены окончательные свойства в promoted-параметрах конструктора.
- **Остальные функции ядра.** `php --ini=diff` показывает директивы `php.ini`, отличающиеся от значений по умолчанию. Константы `PHP_BUILD_DATE` и `PHP_BUILD_PROVIDER` сообщают сведения о сборке PHP. Замыкание, созданное в атрибуте или значении по умолчанию, должно быть `static` и не может захватывать внешние переменные.
- **Расширения.** Новый URI-модуль включён в стандартную поставку. В DOM добавлены `outerHTML`, `insertAdjacentHTML()` и поиск элементов по классу; EXIF получил поддержку HEIF/HEIC; для cURL появились `curl_multi_get_handles()` и постоянные общие дескрипторы. В `intl` добавлены форматирование списков, определение направления письма для локали и `grapheme_levenshtein()`. Параметр `partitioned` доступен для cookie и cookie-сессий. PDO_SQLite, PostgreSQL, SOAP и другие модули получили новые функции и настройки.

Для директивы `max_memory_limit` в конфигурации сервера, например, можно указать:

    ; php.ini
    max_memory_limit = 512M

После этого скрипт всё ещё может выбрать собственный `memory_limit`, но PHP не позволит поднять его выше серверного потолка.

## Что проверить при переходе

В PHP 8.5 устарели некоторые старые формы записи и приведения типов. Замените неканонические касты на короткие имена:

    (integer) $value; // устаревшая форма
    (int) $value;     // актуальная форма

Также используйте двоеточие после `case`, а не точку с запятой:

    switch ($status) {
        case 'ready':
            start();
            break;
    }

Обратные кавычки как сокращение для `shell_exec()` объявлены устаревшими; пишите вызов функции явно. Устарели также некоторые старые no-op функции, методы `__sleep()`/`__wakeup()`, повторное объявление констант и использование `null` как ключа массива или при вызове `array_key_exists()`.

Появились дополнительные предупреждения для сомнительных преобразований, например при приведении слишком большого `float` к `int`, преобразовании `NAN` в другой тип и распаковке не-массива. Они помогают обнаружить код, который раньше продолжал работу с неоднозначным результатом. Проверьте журналы и тесты после переключения версии, особенно если приложение работает с числовыми данными или полагается на неявные преобразования.

Полный перечень новых функций, расширений, несовместимых изменений и устаревшей функциональности дан в [официальном руководстве по миграции с PHP 8.4 на 8.5](https://www.php.net/manual/ru/migration85.php).
