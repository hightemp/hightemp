# Что нового в Docker за 2026 год: Compose Jobs и изменения Engine 29

Срез статьи — 5 октября 2026 года. Последний релиз Engine на эту дату — `29.8.2`, Compose — `5.6.0`. В этом году продолжается ветка Engine 29, а Compose развивает отдельные типы контейнерных задач.

## Совместимость Engine API

Engine 29.0 повысил минимальную поддерживаемую версию API до `1.44`. Это могло затронуть старые SDK, панели управления и CI-клиенты, которые обращаются к daemon по API.

В Engine 29.3 минимальную версию понизили до `1.40`, вернув совместимость с клиентами поколения Docker 19.03 и новее. При обновлении демона проверяйте не только версию CLI: вспомогательные программы могут использовать собственную библиотеку и старый API.

## Engine 29.7: embedded containerd и image mounts

В Engine 29.7 добавили экспериментальный режим, в котором containerd работает внутри процесса Docker daemon, а не как отдельный процесс. Это уменьшает межпроцессное взаимодействие при операциях с образами, особенно когда включён containerd image store.

Настройка выглядит так:

```json
{
  "features": {
    "embedded-containerd": true
  }
}
```

Режим экспериментальный. Если до этого Engine использовал установленный на хосте containerd, его образы и контейнеры не переносятся автоматически в embedded-режим. Для обычного production обновления это не переключатель «ускорить без последствий»; сначала проверьте запуск, хранение и возврат к прежнему состоянию на отдельном узле.

В том же выпуске image mounts перестали быть экспериментальными. Image mount подключает файлы из другого образа в контейнер только для чтения. Это пригодится для общих инструментов и статических ресурсов, которые не хочется копировать в каждый application image. Такая возможность требует containerd image store, а исходный образ нужно предварительно скачать:

```bash
docker pull busybox:musl
docker run --rm \
  --mount type=image,source=busybox:musl,destination=/dbg \
  alpine /dbg/bin/echo "Команда взята из подключённого образа"
```

Контейнер Alpine видит файлы BusyBox внутри `/dbg`, но не меняет смонтированный образ. BusyBox с musl совместим с Alpine; бинарник из образа на другой libc может не запуститься.

## Engine 29.8: задавать umask контейнера

В Docker Engine 29.8.0 появился параметр `--umask`. Он задаёт маску прав для файлов, создаваемых основным процессом контейнера, командами `docker exec` и healthcheck-процессом.

```bash
docker run --rm --umask 0027 my-image
```

При стандартных режимах создания файлов значение `0027` обычно оставляет доступ владельцу и группе, но снимает права у остальных. Фактический результат зависит от того, какие режимы запрашивает приложение. Перед использованием проверьте права файлов в томах.

Например, если процесс создаёт файл с базовым режимом `0666`, с этой маской получится `0640`; для каталога с базовым режимом `0777` — `0750`. Сам umask не меняет права уже существующих файлов.

Самый свежий на дату статьи Engine 29.8.2 вышел 30 сентября и содержит исправления безопасности в Engine и BuildKit. Поэтому ежегодный обзор новых функций не заменяет установку актуальных patch-релизов.

## Compose 5.6: Jobs

Compose 5.6.0, выпущенный 2 октября, добавил частичную поддержку `jobs` — контейнеров для задач, которые выполняются до завершения. В этой версии поддержан ручной запуск. Запуск по расписанию пока не работает, а полная поддержка зависит от будущего Docker Engine.

Это новое понятие Compose Specification; job описывается отдельно от постоянно работающего сервиса. Пока реализация развивается, сверяйте release notes Compose и Engine и не переносите критические расписания без проверки фактической поддержки в используемой версии.

Минимальное описание ручной задачи в Compose 5.6 выглядит так:

```yaml
jobs:
  smoke:
    image: alpine
    command: ["sh", "-c", "echo one-shot job"]
    triggers:
      manual: true
```

`docker compose up` не запускает такие jobs автоматически; вручную её запускают командой `docker compose run smoke`. Это подходит для разового сценария вроде проверки или обслуживания. Поле расписания уже описано в Compose Specification, но v5.6 при попытке запустить проект с активной scheduled job сообщает, что расписания пока не поддерживаются.

## Docker Desktop развивается отдельно

В Desktop в 2026 году Docker объявил Gordon общедоступным и продолжил работу над MCP Toolkit и Docker Model Runner. Это инструменты среды Docker Desktop для разработчика; они не являются изменениями Docker Engine, запущенного на Linux-сервере.
