# Что нового в Docker за 2023 год: containerd image store и Compose Watch

В Docker нет единого номера версии: Docker Engine, Compose и Docker Desktop выпускаются отдельно. В статье собраны заметные изменения, появившиеся за 2023 год в компонентах для запуска контейнеров, разработки и сборки. Статус каждой функции указан на момент её появления: экспериментальная, бета или готовая к использованию.

## Docker Engine 24: экспериментальное хранилище образов на containerd

В Engine 24.0 появилась экспериментальная альтернатива классическому хранилищу образов. Вместо классического image store, связанного с драйвером вроде `overlay2`, экспериментальный containerd image store хранит образы через containerd и его snapshotters.

Практическая причина попробовать его — работа с multi-platform образами в локальном image store. Классическое хранилище не умеет хранить manifest lists и image attestations в том же виде; containerd store открывает путь к локальной работе с несколькими архитектурами и метаданными сборки.

Image store отвечает за хранение содержимого образов и их манифестов. Он не заменяет containerd как runtime: Docker и раньше использовал containerd под капотом для управления жизненным циклом контейнеров. Новшество именно в том, как Engine держит образы на диске и какие их типы может представить локально.

В Engine 24 функция была экспериментальной. Для тестового хоста её включали в конфигурации демона:

```json
{
  "features": {
    "containerd-snapshotter": true
  }
}
```

После изменения нужен перезапуск Docker Engine. Переключение хранилища делает образы и контейнеры из другого хранилища временно невидимыми: их данные остаются на диске, но Docker показывает только активное хранилище. Поэтому проверьте режим на отдельном окружении и сохраните необходимые образы перед переключением. В Engine 29 containerd store стал хранилищем по умолчанию для новых установок; продолжение этой истории — в статье [за 2025 год](whats-new-in-docker-2025.md).

## Compose Watch: синхронизация исходников во время разработки

В Compose 2.22 появился раздел `develop.watch`, а команда `docker compose watch` стала доступна без экспериментального режима. Она следит за выбранными файлами на рабочем компьютере и выполняет одно из действий: синхронизирует файлы в контейнер, перестраивает образ или перезапускает сервис.

```yaml
services:
  app:
    build: .
    develop:
      watch:
        - action: sync
          path: ./src
          target: /srv/app/src
          ignore:
            - vendor/
        - action: rebuild
          path: composer.json
```

Запустить проект с отслеживанием изменений можно командой:

```bash
docker compose up --watch
```

Изменения в `src/` попадут в работающий контейнер; изменение `composer.json` запустит новую сборку, чтобы применить зависимости. Пути в правилах задаются относительно каталога проекта. Контейнер должен разрешать запись в путь `target`, а файлы, указанные в `.dockerignore`, Compose Watch тоже пропускает.

`sync` копирует изменённые файлы, не пересоздавая контейнер; `rebuild` перестраивает образ и пересоздаёт сервис. Это разные действия: например, PHP-файл удобно синхронизировать, а изменения `composer.json` требуют пересборки образа с установленными пакетами. В образе должны быть необходимые служебные команды для Watch, а процесс контейнера должен иметь права на каталог назначения.

Compose Watch рассчитан на локальную разработку с сервисами, собираемыми из исходников. Это удобный способ сократить цикл «изменить код — пересобрать», он не подменяет процесс сборки и выкладки production-образов. Позже Compose добавил дополнительные действия для Watch.

## Docker Desktop: переход на Compose v2 и шаблон для PHP

В Docker Desktop 4.23 устаревшее приложение Compose v1 перестало поставляться вместе с Desktop. Вместо команды `docker-compose` используется плагин `docker compose` с пробелом; Compose v2 входит в современный Docker CLI.

В Desktop 4.26 команда `docker init` получила бета-шаблон для PHP-приложений с Apache и Composer. Она задаёт начальную структуру Dockerfile и Compose-проекта, которую всё равно нужно просмотреть под требования конкретного приложения. Это хорошая отправная точка для локальной разработки, а не готовая production-конфигурация.

Команда запускается из каталога проекта и создаёт начальные `.dockerignore`, `Dockerfile`, `compose.yaml` и `README.Docker.md`. Перед запуском проверьте, не существуют ли эти файлы: если согласиться на перезапись, восстановить старое содержимое автоматически не получится.

## Что проверить, если обновляете старый Engine

В Docker Engine 24 удалили давно устаревшие драйверы `aufs` и `overlay`. Драйвер `overlay2` этим изменением не затронут. На старых серверах перед обновлением проверьте используемый storage driver: это часть состояния Engine, и её нужно учитывать в плане миграции.

Другие обновления года были исправлениями безопасности и надёжности. Для полной истории смотрите релиз-ноты конкретного минорного выпуска: стабильные обновления Engine 24 продолжались и в 2024 году.
