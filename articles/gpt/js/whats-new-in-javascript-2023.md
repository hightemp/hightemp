# Что нового в JavaScript за 2023 год: новые способы работы с массивами

В 2023 году вышла 14-я редакция стандарта ECMAScript — ES2023. Главный практический акцент этого выпуска — операции с массивами, которые возвращают копию и не меняют исходные данные. Статья описывает изменения языка и стандартных встроенных объектов; API браузеров и Node.js имеют отдельные циклы обновления.

## Методы массива, которые не меняют исходный массив

Раньше для сортировки, разворота или замены элемента часто приходилось сначала копировать массив либо вручную сохранять его исходное содержимое. ES2023 добавил методы-копии:

- `toSorted(compareFn)` сортирует копию; при сравнении чисел передавайте компаратор;
- `toReversed()` возвращает копию с обратным порядком;
- `toSpliced(start, deleteCount, ...items)` возвращает копию после вставки или удаления;
- `with(index, value)` возвращает копию, в которой заменён один элемент.

    const scores = [30, 10, 20];

    const sorted = scores.toSorted((a, b) => a - b);
    const reversed = scores.toReversed();
    const corrected = scores.with(-1, 25);
    const edited = scores.toSpliced(1, 1, 15);

    console.log(sorted);    // [10, 20, 30]
    console.log(reversed);  // [20, 10, 30]
    console.log(corrected); // [30, 10, 25]
    console.log(edited);    // [30, 15, 20]
    console.log(scores);    // [30, 10, 20] — исходный массив не изменился

`toSpliced()` похож на `splice()`, но не редактирует массив на месте: он возвращает новую версию. `with()` принимает отрицательный индекс для отсчёта с конца. Эти методы доступны также типизированным массивам, кроме `toSpliced()`.

Такой стиль помогает, когда исходный список ещё нужен в другом месте: например, один массив можно безопасно передать в интерфейс, а другой — отсортировать для отчёта.

## Поиск с конца

`findLast()` и `findLastIndex()` ищут элементы справа налево. Первый возвращает значение, второй — индекс найденного элемента:

    const events = [
        { type: 'error', message: 'timeout' },
        { type: 'info', message: 'retrying' },
        { type: 'error', message: 'unavailable' },
    ];

    const lastError = events.findLast(event => event.type === 'error');
    const lastErrorIndex = events.findLastIndex(
        event => event.type === 'error',
    );

    console.log(lastError.message); // unavailable
    console.log(lastErrorIndex);   // 2

Обычные `find()` и `findIndex()` ищут слева направо. Новые методы удобны, когда нужен самый поздний подходящий элемент в журнале или списке событий. Они также доступны типизированным массивам.

## Файлы-скрипты с hashbang

В начале JavaScript-файла разрешена строка вида `#!/usr/bin/env node`:

    #!/usr/bin/env node
    console.log('Привет из командной строки');

Это позволяет запускать файл как исполняемый скрипт в Unix-подобных системах, если файл имеет право на запуск. Строка hashbang должна стоять в самом начале файла; её смысл зависит от операционной системы, а не от кода приложения.

## Символы в weak-коллекциях и слабых ссылках

До ES2023 ключами `WeakMap` и элементами `WeakSet` могли быть только объекты. Теперь для слабых ссылок подходят также символы, у которых есть собственная идентичность и которые можно собирать сборщиком мусора:

    const metadata = new WeakMap();
    const pluginKey = Symbol('plugin');

    metadata.set(pluginKey, { enabled: true });
    console.log(metadata.get(pluginKey).enabled); // true

Так же символы разрешены в `WeakSet`, `WeakRef` и `FinalizationRegistry`. Зарегистрированные глобально символы, созданные через `Symbol.for()`, исключены: реестр удерживает их, поэтому слабая ссылка не могла бы помочь освободить их. Встроенные well-known symbols, например `Symbol.iterator`, разрешены, но обычно живут столько же, сколько сам JavaScript realm, поэтому использовать их как weak-ключ ради освобождения памяти не имеет смысла.

## Что учитывать при переходе

Самое заметное изменение для прикладного кода — новые методы-копии нужно вызывать вместо мутирующих вариантов, если требуется сохранить исходный массив. Старые `sort()`, `reverse()` и `splice()` по-прежнему меняют массив.

Поддержка новой редакции появляется в движках постепенно. Перед использованием проверьте версию браузера или Node.js, с которой должно работать приложение; транспилятор не всегда может заменить поведение встроенных объектов без полифилла.
