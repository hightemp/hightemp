# Что нового в CSS за 2023 год: контейнеры, :has(), subgrid и нативная вложенность

2023 год изменил подход к компонентной вёрстке: карточка смогла реагировать на собственное окружение, селектор — учитывать содержимое элемента, а вложенная сетка — использовать линии родительской. Несколько возможностей существовали в отдельных браузерах раньше; именно в 2023 году container queries, `:has()`, subgrid и nesting получили межбраузерную поддержку. [Baseline 2023](https://web.dev/baseline/2023)

У CSS нет одного ежегодного выпуска наподобие ES2023. Стандарты развиваются модулями, а браузеры внедряют их независимо. Поэтому здесь рассматриваются важные изменения реализаций и совместимости, а не вымышленная редакция «CSS 2023». Поддержка и примеры сверены **5 ноября 2026 года**; особенности, доступные только части браузеров, отмечены отдельно.

## Container queries: адаптация к ширине контейнера

Media query отвечает на вопрос «какова ширина окна?». Для карточки внутри sidebar это не всегда полезно: окно большое, а доступное карточке место маленькое. Size container query проверяет размер подходящего предка:

```html
<div class="product-slot">
  <article class="product-card">
    <img src="keyboard.jpg" alt="Механическая клавиатура">
    <div>
      <h2>Клавиатура</h2>
      <p>Описание товара</p>
    </div>
  </article>
</div>
```

```css
.product-slot {
  container: product / inline-size;
}

.product-card {
  display: grid;
  gap: 1rem;
}

.product-card img {
  inline-size: 100%;
  block-size: auto;
}

@container product (min-width: 36rem) {
  .product-card {
    grid-template-columns: 12rem 1fr;
    align-items: center;
  }
}
```

`container` объединяет имя `product` и тип `inline-size`. В обычном горизонтальном письме проверяется доступная ширина. При достаточном месте карточка становится двухколоночной независимо от того, находится она на всю страницу или в узкой панели.

Контейнером выбран **внешний элемент**: size query не позволяет элементу выбирать собственную геометрию в зависимости от неё же. Containment также влияет на расчёт размеров контейнера, поэтому не стоит без разбора ставить `container-type` всем элементам.

Появились контейнерные единицы `cqw`, `cqh`, `cqi`, `cqb`, `cqmin`, `cqmax`. Например, `1cqi` — 1% inline-размера подходящего query-контейнера. Их можно использовать с `clamp()` для масштабирования типографики компонента. Если подходящего контейнера нет, используются соответствующие small viewport размеры, поэтому отсутствие контейнера может незаметно поменять результат. [Container size queries](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_size_and_style_queries)

## `:has()`: стиль зависит от содержимого

Раньше для оформления карточки с картинкой часто добавляли класс из JavaScript или шаблонизатора. Теперь наличие подходящего элемента можно выразить селектором:

```css
.card {
  padding: 1rem;
}

.card:has(> img) {
  padding-block-start: 0;
}

.field:has(input:user-invalid) {
  border-inline-start: 3px solid #b42318;
}
```

Первое правило выбирает `.card` с непосредственным дочерним `img`. Второе позволяет выделить обёртку поля, когда вложенный input считается невалидным после взаимодействия пользователя.

`:has()` — **relational selector**, поэтому умеет учитывать не только потомков. Например, `h2:has(+ p)` выбирает заголовок, сразу за которым идёт абзац. Он не перемещает элементы и не меняет DOM.

Специфичность зависит от наиболее специфичного селектора аргумента, а не от фиксированного веса псевдокласса. Большие выражения с ID могут неожиданно усилить правило. Для производительности полезно ограничивать область конкретным компонентом, а не начинать каждую проверку с `body:has(...)`. [Справочник :has()](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/:has)

## Subgrid: карточки разделяют родительские строки

Обычный вложенный grid создаёт собственные tracks. Поэтому заголовок, описание и кнопка соседних карточек могут перестать совпадать по высоте. Subgrid позволяет использовать строки родителя:

```html
<div class="products">
  <article class="product">
    <h2>Короткое название</h2>
    <p>Описание</p>
    <button>Купить</button>
  </article>
  <article class="product">
    <h2>Название товара на несколько строк</h2>
    <p>Более длинное описание товара.</p>
    <button>Купить</button>
  </article>
</div>
```

```css
.products {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
  gap: 1rem;
}

.product {
  display: grid;
  grid-template-rows: subgrid;
  grid-row: span 3;
}
```

Каждая карточка занимает три родительские строки и размещает в них три дочерних элемента. Заголовки, описания и кнопки выравниваются по общим tracks. Не приходится фиксировать высоту заголовка, угадывая количество строк.

Можно наследовать колонки, строки или обе оси. Subgrid должен быть grid item родителя; одного объявления `subgrid` у произвольного вложенного элемента недостаточно. В браузере без поддержки нужен обычный layout карточки как fallback. [Subgrid](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Subgrid)

## Native nesting: вложенные правила без препроцессора

Браузеры научились разбирать вложенные CSS-правила напрямую:

```css
.button {
  padding: 0.65rem 1rem;
  border: 1px solid #344054;

  &:hover {
    background: #eef2ff;
  }

  & > .icon {
    inline-size: 1em;
  }

  @media (width >= 50rem) {
    padding-inline: 1.5rem;
  }
}
```

`&` обозначает родительский селектор. `&:hover` применяется к самой кнопке, `& > .icon` — к её непосредственному потомку.

Нативная вложенность не повторяет весь Sass. Например, Sass-приём `&__icon` для конкатенации имени класса не превращается в `.button__icon` средствами CSS. Вложенность также не вводит Sass-переменные, mixins и циклы.

Ранние браузерные реализации nesting различались; в 2023 году синтаксис ещё уточнялся. Для старой целевой матрицы разумно преобразовывать вложенность сборщиком. Глубокие цепочки селекторов остаются трудными для сопровождения и без препроцессора. [CSS Nesting](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Nesting/Using)

## Новые цветовые пространства и `color-mix()`

CSS Color 4 дал полноценные `lab()`, `lch()`, `oklab()`, `oklch()` и `color()`. Они позволяют выбирать цвет в других пространствах и работать с широким gamut:

```css
.accent {
  color: #315ae6;
  color: oklch(58% 0.2 265);
}
```

В `oklch()` параметры — светлота, chroma и hue. Светлота не означает непрозрачность; alpha указывается отдельно после `/`. Возможность записать широкий gamut не гарантирует, что дисплей воспроизведёт его без преобразования. [Цветовые пространства](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/color_value/oklch)

`color-mix()` смешивает два цвета в выбранном пространстве:

```css
.badge {
  background: #e8edf7;
}

@supports (background: color-mix(in oklab, red, white)) {
  .badge {
    background: color-mix(in oklab, #315ae6 15%, white);
  }
}
```

Здесь 15% акцентного цвета смешивается с 85% белого. Пространство интерполяции влияет на результат; это не просто усреднение записанных RGB-чисел. Если процент одного цвета опущен, он дополняет указанный процент до 100%. [Параметры color-mix()](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/color_value/color-mix)

## `:nth-child(... of ...)`: считать только подходящие элементы

```css
.results > :nth-child(2n of .result:not([hidden])) {
  background: #f2f4f7;
}
```

Сначала формируется список подходящих siblings, затем выбирается каждый второй элемент этого списка. Это отличается от `.result:nth-child(2n)`, где позиция считается среди всех соседних элементов. Удобно для чередования видимых строк, когда между ними есть служебные элементы. [Синтаксис nth-child](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/:nth-child)

## Другие изменения года

| Возможность | Что даёт |
| --- | --- |
| `:user-valid` / `:user-invalid` | Стили состояния поля после подходящего взаимодействия, без немедленной ошибки у каждого пустого required-input |
| `lh` / `rlh` | Размеры относительно line-height элемента / корневого элемента |
| `sin()`, `cos()`, `tan()` и другие функции | Геометрические вычисления непосредственно в CSS |
| `linear()` | Easing с последовательностью контрольных точек |
| `animation-composition` | Управление тем, как эффект анимации сочетается с основным значением |
| Range syntax media queries | Условия вроде `(30rem <= width < 60rem)` |

Не всё из популярных обзоров CSS 2023 сразу стало межбраузерным: View Transitions, scroll-driven animations, `@scope`, style queries и entry transitions тогда только начинали распространяться. Их дальнейшее развитие описано в следующих статьях. [Обзор браузерных новшеств 2023](https://developer.chrome.com/blog/css-wrapped-2023)

## Поддержка и внедрение

Для основной группы функций milestone **Baseline Newly available пришёлся на 2023 год**. Это поддержка в основных актуальных браузерах на соответствующую дату, а не во всех старых браузерах. Baseline Widely available присваивается через 30 месяцев; к ноябрю 2026 года перечисленные основные возможности 2023 года уже прошли этот период. Источник дат — [данные WebDX web-features](https://github.com/web-platform-dx/web-features).

Рабочий порядок: оставить простую исходную вёрстку, поверх неё добавить поддержку через `@supports`, затем сверить реальные требования проекта. Например, отсутствие subgrid не должно делать карточку нечитаемой, а отсутствие `:has()` — отключать серверную валидацию формы.
